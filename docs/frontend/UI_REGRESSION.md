# UI regression correction cycle (after ed86d51)

Scope: targeted corrections only; no redesign, no new features, no backend change, no auth/permission/dispatch-rule change. Evidence: `docs/evidence/UI_REGRESSION/` (19 screenshots captured after the fixes, test geography = bundled Natural Earth + BBMP wards; no regional archive and no fixture was loaded, so nothing here shows South India street data).

Note on the supplied screenshots: they were not attached to the conversation I received, so each item below was reproduced and verified from code and fresh browser output rather than from your images.

## Investigations
**Routing (screenshot 1 "Page not found").** Routes are server-driven (`backend/app/core/navigation.py`): the public home is `/`, public pages `/public/<slug>`, console pages `/console/<slug>`, account `/account`. `/public/home` is not a route, so "Page not found" there is the genuine 404 (my own earlier capture used that URL). Verified in a browser (fresh DB): `/`, `/login`, `/signin`, `/register`, `/console/overview`, `/account`, unknown paths -> sign-in screen when signed out; `/public/flood-twin` -> guest portal; `?reset=` and `#invite=` -> reset/invitation screens; refresh/back/forward keep the page; sign-out returns to `/`. Two real defects found and fixed: (1) a guest on `/public/...` who clicked Sign in and signed in to the console landed on "You do not have access to this page" (old address not valid in the new workspace); now a fresh sign-in from the login screen lands on the new workspace's start page (authorization unchanged, restored sessions untouched); (2) friendly aliases `/public`, `/public/home`, `/console`, `/console/home` open the start page. The 404 page remains for genuinely invalid routes (screenshot 19, labelled error-state test).

**Overview overlap (screenshots 3, 6, 7).** Root cause was a class collision: my Navigation info card used `.map-card { position:absolute }`, and the Overview panel also used `class="map-card"`. I verified in git that `ed86d51` already contained the rename (`.map-card` has 0 references in its `shell.css`, 7 `rn-info-card`), so screenshots showing the overlap predate that commit or came from a stale dev build. Regardless, the layout is now restructured and guarded by a test (below).

**Forecasting numbers.** The "97.5% / F1 0.94" text is `confidence_level` from `backend/app/ml/flood_model.py`: the mean 5-fold stratified cross-validation accuracy and F1 on the same 1,000-record dataset. It is not an independent hold-out figure (the 20% hold-out accuracy is a separate metric). The classifier uses 3 inputs (rainfall, humidity, temperature). Water level is the fourth slider but not a classifier input: it only applies a gauge rule that can raise the risk class (>= 2.5, 3.8, 5.5 m) and is listed as a factor with 0% model weight. The +30/+45/+60 projections use only the classifier probability and the rainfall input (`prob + rainfall/100*0.15*k`), so water level does not change them. The backend `data_source` string says "real sensor telemetry"; that provenance is not verified, and the UI keeps saying "supplied with the project, collection method not independently verified". No model, prediction or metric was changed.

## Automated visual regression sweep (Playwright, tile hosts blocked)
Every page offered to each role, at 360, 390, 768, 1024, 1440 and 1920 px, in light and dark: page-level horizontal overflow, overlap between cards/panels/map frames, map frame inside the main area and not over the sidebar, map size, approximate text contrast, browser console/page errors. Roles: guest, citizen, officer, commander, admin, developer. Results: the first full run (552 page-views, 6 roles, both themes, 6 widths) found 0 console errors and one real defect class that I then fixed: the public header overflowed horizontally on narrow phones (4 px for guests at 360 px; 32 px at 360 px and 2 px at 390 px for signed-in citizens). After the fix, guest and citizen were re-run (144 page-views): 0 findings. Earlier sweeps also found and fixed ~20 low-contrast light-theme texts; the last all-role run reported no contrast findings in either theme. Auth screens (sign in, register, forgot, reset, invitation, 404) at 360/768/1440 in both themes: 36 views, 0 findings.

## Regression tests added
`src/regression.test.tsx`: (1) no stylesheet gives an Overview class `position: absolute|fixed` (this fails on the old `.map-card`), (2) Overview grid rules, (3) map frame is an isolated stacking context and no header/drawer/dropdown uses z-index >= 1000, (4) public drawer opens/closes, Esc returns focus, closes after navigation, exactly one theme control, (5) ThemeMenu options, checkmark, trigger icon label, cross-tab sync. `src/lib/theme.test.ts` (4) and `Map/regional.test.ts` (6) from the previous cycle remain.

## Regional pipeline changes
`scripts/windows/regional-gis.ps1`: required Planetiler options are now validated against `--help-all`; if any is missing the script stops and names it (nothing is silently dropped). `Build` refuses to run without a prior `Benchmark` and an explicit `-Approve` (the 8-11 GB estimate is not auto-approved). Benchmark and Build report measured peak memory and peak temp-folder size. The script is still unexecuted on Windows. No regional processing was done in the cloud and the actual South India archive has not been generated.

- Keyboard navigation was verified for the theme menu, drawers and map panels by unit tests and the focus code; a full manual keyboard pass over every page was not done.
- Session-expiry redirect and MFA routes were not re-tested here (code unchanged).
- Rescue Operations has no pagination or search-in-table beyond the existing filters; none was added.
